## OPEN, record-class: the item counter (critique C36, 2026-10-20) — not started

A top redstoner counts large N with an ITEM counter, not a ring: one dropper (or hopper) holding exactly N items, each input pulse moving one item out, a comparator reading EMPTY, and the items returned afterwards. That is CONSTANT size, about 6-10 blocks, for any N up to 576 (27 slots x 64, or 27 for unstackables), while our rings grow with N: counter 25 = 72 blocks, counter 19 = 54, counter 38 = 57, counter 39 = 46. Nothing in the archive counts that way, so every large-N counter here is beatable, and the honest next move is to build it: load a dropper with N items, fire it from the input, read "empty" with a comparator (level 0) and feed the items back (a hopper under the dropper's output returning to it, or a second dropper firing back on the empty signal). Then judge it across a spread of N and keep a ring only where it genuinely wins - nothing to preload, instant reset, no item entities, no refill latency between laps - with that reason written on the page.

Two checks the critique asked for, both verified against designs/circuits/memory/archive/verdicts.tsv:
- "counter 38 = 57 blocks beside counter 48 = 20 blocks" is NOT a mislabel. A composite N chains into small rings (48 = 3 x 4 x 4, or bulbs), while a prime factor forces one long ring (38 = 2 x 19 needs a 19-ring). Size tracks the factorisation, not N.
- Same-N pairs where one is strictly bigger ARE dominated and should be folded (`variant_of`) or dropped, with the same metric line: counter9-ring9 25b vs counter9-ring3-ring3 17b; counter16-ring4-ring4 20b vs counter16-bulb4 12b; counter18-ring9-bulb1 28b vs counter18-ring3-ring3-bulb1 20b; counter20-ring5-ring4 22b vs counter20-ring5-bulb2 17b; counter12-ring3-ring4 18b vs counter12-ring3-bulb2 14b; counter4-ring 10b and counter4-ring9 9b vs counter4-bulb2 6b; counter5-star 12b vs counter5-ring11 11b; counter2-ring 8b vs counter2-bulb 3b. (counter3-corner and counter3-ring are both 8b: equivalent layouts, not domination. The `-div` entries are a different output style - "output toggles every N" - so they are not dominated by the level-style ones.)

## Done 2026-10-20 (critique C27)
