name: gadget-landing-race
# Which piston fires first when a moving block lands between two powered pistons? Sticky piston
# Q holds redstone block R away from piston A. Lever off: Q retracts and pulls R next to A, and
# the sculk sensor S re-powers Q at t2 while it is still moving. Q lands at t3 just before R (its
# moving block entity is older) but cannot queue its push yet: R is still a moving block, so the
# push does not resolve (gadget no-retry). R then lands and updates its neighbours in the order
# WEST, EAST, DOWN, UP, NORTH, SOUTH (gadget event-order); A (powered by R) and Q (whose push now
# resolves) both queue there. Here Q is west of R and A south of it: Q's push runs first at t4,
# takes R away, and A's event is dropped (no signal any more), so stone X never moves. Turned 90
# degrees (landing-race-turned.txt: A west of R, Q north) A goes first: it starts pushing X,
# Q takes R away, A retracts in the same block-event phase and spits X one cell down. This is
# why sculk-2's s4/s1 doors broke facing east/west (tracks/sculk-ew/NOTES.md).
origin: -1 0 0
palette:
  L minecraft:lever[face=wall,facing=west,powered=true]
  K minecraft:smooth_stone
  X minecraft:stone
  Q minecraft:sticky_piston[extended=true,facing=east]
  H minecraft:piston_head[facing=east,short=false,type=sticky]
  R minecraft:redstone_block
  A minecraft:sticky_piston[extended=false,facing=down]
  S minecraft:sculk_sensor[power=0,sculk_sensor_phase=inactive,waterlogged=false]
layer 1:
  LK
  ..X
layer 2:
  .QHR
  ..A
layer 3:
  .S
